## Как запустить

```bash
python test_analysis.py
python main.py
python fetch_profile.py      # если доступна сеть

```

`main.py` сначала читает `todos.json`, затем спрашивает `user_id` и подстроку для названия. При корректном входе пишет `leaders.json` и `selected.json`.

## Формат `todos.json`

Список объектов; у каждой записи:
- `id` — положительное целое, уникальное;
- `userId` — положительное целое;
- `title` — непустая строка;
- `completed` — `true`/`false` (`bool`).

Дополнительные ключи разрешены. Проверка `id` — через `type(x) is int` (булево `True` не должно считаться `int`), `completed` — через `type(x) is bool`. Нарушение — `ValueError` с пояснением.

## Анализ

- `completion_counts(todos)` — `{userId: число завершённых}` для всех пользователей набора, включая тех, у кого ноль завершённых. Для учебного набора: `{5: 2, 10: 2}`.
- `top_users(counts)` — отсортированный список `userId` с максимальным числом завершённых; при пустом словаре или максимуме `0` — `[]`. Для набора: `[5, 10]`.
- `leaders.json` — завершённые задачи лидеров в исходном порядке: id `[1, 3, 4, 5]`. `userId` остаются числами; в строку преобразуются только при печати.

## Вариант 9

`select_tasks(todos, user_id, parameter=None)`:
1. Сначала отбираются задачи пользователя `user_id`.
2. Если `parameter` передан, оставляем те, у которых `title.lower().startswith(parameter.strip().lower())` — без учёта регистра.
3. Порядок записей сохраняется; исходные записи не изменяются.

В `main.py` `user_id` вводится с повторным вводом (вариант 9 явно требует это), подстрока — непустая строка после `strip()`. Это **явные ограничения** из условия варианта; по общему правилу «до работы №10 доверяем типу» ничего сверх них не делаем.

| Вход | Ожидание | Факт |
|---|---|---|
| `user_id=5`, `parameter="с"` | id `[5]` | `[5]` |
| `user_id=5`, `parameter="С"` | id `[5]` (регистр не важен) | `[5]` |
| `user_id=10`, `parameter="с"` | id `[3]` (`Строки`) | `[3]` |
| `user_id=999`, `parameter="с"` (неизвестный) | `[]` | `[]` |
| `user_id=10`, `parameter="х"` (нет совпадений) | `[]` | `[]` |

`selected.json` для `user_id=5`, `parameter="с"`:

```json
[{"id": 5, "userId": 5, "title": "Списки", "completed": true}]
```

## Ошибки и сохранность результатов

`main.py` обрабатывает:
- `FileNotFoundError` — файла нет;
- `UnicodeError` — файл не в UTF-8;
- `json.JSONDecodeError` — невалидный JSON (обработчик стоит **раньше** общего `ValueError`, потому что это его подкласс);
- `ValueError` — нарушение структуры;
- `OSError` — прочие ошибки доступа (например, нет прав).

Результаты пишутся **только после** успешной проверки. Если `todos.json` отсутствует, содержит не-JSON, неверную структуру или файл не читается, прежние `leaders.json`/`selected.json` остаются без изменений. Входной файл открывается только на чтение.

## HTTP-упражнение

`fetch_profile.py`:
- **Адрес** `https://api.github.com/users/<login>` — ресурс профиля пользователя GitHub (а не репозитория: для репозитория нужны владелец и имя).
- **GET** — метод чтения ресурса; `urlopen` по умолчанию выполняет GET.
- **Таймаут** `timeout=10` — ограничивает время ожидания ответа, чтобы программа не зависала при недоступной сети.
- **Обработчики**:
  - `HTTPError` — сервер ответил, но с кодом ошибки (`404` — нет пользователя, `403`/`429` — ограничения), печатаем `HTTP <код>`;
  - `URLError` / `TimeoutError` / `socket.timeout` — сеть недоступна или таймаут;
  - `ValueError` / `UnicodeError` — пустой логин, ответ не похож на профиль, проблемы кодировки;
  - `OSError` — проблемы записи `profile.json`.

Ответ сохраняется в `profile.json` без выдумывания отсутствующих полей: если значение `null`, оно остаётся `null`.

**Без сети.** Используется локальный `profile_sample.json` (`{"login": "demo", "id": 1, "name": null}`) через `offline_demo.py`; вывод: `Логин (локальный пример): demo`. Это учебные локальные данные, режим равноценен сетевому по методичке.

## Ответы на вопросы

**Ошибки формата vs ошибки доступа.** Ошибки формата — «файл открылся, но содержимое не по правилам»: не JSON (`JSONDecodeError`), не список, запись не объект, нет `id`/`userId`, `id` повторный, `title` пустой, `completed` не `bool`. Это `ValueError`. Ошибки доступа — «файл не открыть по причинам ОС»: `FileNotFoundError`, `PermissionError`, `OSError`. Кодировка — отдельно (`UnicodeError`, частный `ValueError`), её обработчик стоит раньше общего.

**Почему результаты открываются для записи только после проверки.** Режим `"w"` стирает прежнее содержимое в момент открытия. Если открыть `leaders.json`/`selected.json` до проверки `todos.json`, при любой ошибке входа старые результаты уже исчезнут. Порядок в `main.py` такой: прочитать `todos.json`, проверить структуру, посчитать количества и лидеров, и только затем записать `leaders.json`. Аналогично `selected.json` пишется после успешного ввода `user_id` и подстроки. Так требование «при ошибке входных данных не перезаписывайте прежние результаты» выполняется.

**Сетевые вызовы не выполняются при импорте.** `fetch_profile.py` и `offline_demo.py` — отдельные скрипты, `test_analysis.py` их не импортирует; `urlopen` вызывается только из `main()` под `if __name__ == "__main__":`.
