## Таблица трассировки: сумма чисел 1–4

Для цикла:

```python
total = 0
for number in range(1, 5):
    total += number
```

| Итерация | `number` | `total` до | `total` после |
|---|---|---|---|
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |

Итог: `total = 10`. `range(1, 5)` даёт `1, 2, 3, 4` (5 не входит).

## Проверки `range_numbers.py`

| № | Вход `(a, b)` | Ожидаемый вывод | Фактический вывод |
|---|---|---|---|
| 1 (из условия) | `2, 4` | `2`, `3`, `4` (по строкам) | совпадает |
| 2 (из условия) | `4, 2` | `4`, `3`, `2` (по строкам) | совпадает |
| 3 (из условия) | `3, 3` | только `3` | совпадает |
| 4 | `0, 3` | `0`, `1`, `2`, `3` | совпадает |
| 5 | `1, 1` | `1` | совпадает |
| 6 | `-2, 1` | `-2`, `-1`, `0`, `1` | совпадает |
| 7 | `-1, -3` | `-1`, `-2`, `-3` | совпадает |

**Почему `range(a, b)` не всегда подходит.** `range(a, b)` строит `a, a+1, …, b-1` — правый конец **не включается**. Для возрастания нужен `range(a, b + 1)`; для убывания `range(a, b - 1, -1)` (потому что `range(4, 2, -1)` дал бы `4, 3` — без `2`). Также `range(a, b)` при `a > b` пуст, поэтому его одного недостаточно для «убывания».

## Краткие ответы

1. **Почему цикл завершится.**
   - `range_numbers.py` — цикл `for` по `range(...)` идёт по конечной последовательности, каждая итерация уменьшает «остаток» до `stop`.
   - `statistics.py` — `for i in range(2, n + 1)` выполняет ровно `n − 1` итераций (плюс отдельное чтение первого числа).
   - `positive_input.py` — `while` завершится, когда пользователь введёт положительное число (условие `value <= 0` станет ложным).
   - `variant.py` — `for i in range(1, n + 1)` выполняет ровно `n` итераций, включая `n = 0` (0 итераций).
   - `prime.py` — `divisor` увеличивается на 1 на каждой итерации, а `divisor * divisor` растёт быстрее `n`, поэтому рано или поздно условие ложно; при нахождении делителя срабатывает `break`.
2. **Почему `range(a, b)` не всегда подходит.**
   - Правый конец `b` не включается — нужен `range(a, b + 1)`.
   - При `a > b` и положительном шаге `range(a, b)` пуст — для убывания нужен `range(a, b - 1, -1)`.
3. **Почему максимум инициализируется первым числом.** Нулевая инициализация даёт неверный ответ для набора из одних отрицательных чисел: `max(0, -5, -2) = 0`, а правильный максимум — `-2`.
4. **`and`/`or` и равенство.** В `variant.py` отбор `value != 0` пропускает и положительные, и отрицательные; ноль исключается одним условием. В `positive_input.py` граница `value <= 0` отсекает `0` (ноль — не положительное), поэтому `0` считается отклонённой попыткой.
