## Обязательное задание 3. Предскажите результат

### Ручной прогноз

| Выражение | Прогноз (вручную) | Результат Python | Совпало? |
|---|---|---|---|
| `2 + 3 * 4` | `14` | `14` | да |
| `(2 + 3) * 4` | `20` | `20` | да |
| `17 // 5` | `3` | `3` | да |
| `17 % 5` | `2` | `2` | да |
| `-7 // 2` | `-4` | `-4` | да |

### Объяснение

- **`2 + 3 * 4 = 14`.** Умножение выполняется раньше сложения: сначала `3 * 4 = 12`, потом `2 + 12 = 14`.
- **`(2 + 3) * 4 = 20`.** Скобки меняют порядок: сначала `2 + 3 = 5`, потом `5 * 4 = 20`.
- **`17 // 5 = 3`.** `//` — деление с округлением **вниз** до целого: `17 / 5 = 3.4`, вниз — `3`.
- **`17 % 5 = 2`.** Остаток от деления: `17 = 3 * 5 + 2`.
- **`-7 // 2 = -4`.** Деление с округлением вниз: `-7 / 2 = -3.5`, вниз до целого — `-4`. (Не «отбрасывание дробной части», а именно округление вниз.)
- Проверка связи: `-7 == (-7 // 2) * 2 + (-7 % 2)` → `-4 * 2 + 1 = -7`. Остаток `-7 % 2 = 1` — знак остатка совпадает со знаком делителя.

Расхождений между прогнозом и результатом Python нет.

## Проверки `time_parts.py`

| № | Вход | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| 1 | `0` | `0 ч 0 мин 0 с` | совпадает |
| 2 | `59` | `0 ч 0 мин 59 с` | совпадает |
| 3 | `60` (отдельный запуск) | `0 ч 1 мин 0 с` | совпадает |

Формулы:

- часы: `total_seconds // 3600`

- секунды: `total_seconds % 60`

Используются только `//` и `%`, модуль `time` не применяется.

## Проверки `variant.py` (вариант 9)

Тема: **количество билетов и билетов в пачке**.

| № | Вход (`total, capacity`) | Ожидаемый результат (`full_packs`, `remainder`, `total_packs`) | Фактический результат |
|---|---|---|---|
| 1 (граница) | `0, 10` | `0`, `0`, `0` | совпадает |
| 2 | `20, 10` | `2`, `0`, `2` | совпадает |
| 3 | `21, 10` | `2`, `1`, `3` | совпадает |
| 4 (больше пачки в 1.5 раза) | `15, 10` | `1`, `5`, `2` | совпадает |
| 5 (одна пачка целиком) | `10, 10` | `1`, `0`, `1` | совпадает |
| 6 (capacity больше total) | `3, 10` | `0`, `3`, `1` | совпадает |
| 7 (крупные числа) | `1000, 7` | `142`, `6`, `143` | совпадает |

Формулы:

- полные пачки: `total // capacity`
- остаток: `total % capacity`
- всего пачек: `(total + capacity - 1) // capacity` — «потолок» без `math.ceil` и без условий.

Проверка вручную (вариант 3): `21 // 10 = 2`, `21 % 10 = 1`, `(21 + 10 - 1) // 10 = 30 // 10 = 3`. Совпадает.

Проверка при `total = 0`: `0 // 10 = 0`, `0 % 10 = 0`, `(0 + 10 - 1) // 10 = 9 // 10 = 0`. Ноль пачек — как и требует условие.

При радиусе `1`: `2 * 3.14159265... = 6.283...` → `6.28`; `3.14159265...` → `3.14`. Округление `:.2f` выполняет форматирование при выводе; само значение `math.pi` не меняется.

## Краткие ответы

1. **`/` и `//`.** `/` — обычное деление, результат `float` (`7 / 2 == 3.5`). `//` — деление с округлением вниз (`7 // 2 == 3`, `-7 // 2 == -4`). В `time_parts.py` и `variant.py` нужен `//`, потому что нужны полные часы/минуты/пачки, а не дробные.
2. **Смысл остатка.** `a % b` — сколько остаётся «лишнего» после выделения `a // b` целых частей: `a == (a // b) * b + a % b`. Это и есть «оставшиеся секунды», «остаток билетов», «остаток сверх целых пачек».
3. **Форматирование и `float`.** `:.2f` только **округляет при выводе**, а хранимое число остаётся приближённым. Например, `0.1 + 0.2` хранится как `0.30000000000000004`; `f"{0.1 + 0.2:.2f}"` покажет `0.30`, но значение по-прежнему приближённое. Поэтому в денежных задачах этой работы используются целые рубли, а не `float`.
4. **Почему в `variant.py` нет `if`.** По условию циклы и условия пока запрещены; «потолок» числа пачек вычисляется формулой `(total + capacity - 1) // capacity`, которая правильно возвращает `0` при `total = 0`.
