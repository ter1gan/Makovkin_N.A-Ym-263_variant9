## Формат `data.json`

Список записей; поля: `id` (положительное целое, уникальное), `title` и `category` (непустые строки после `strip()`), `amount` (целое ≥ 0, для варианта 9 — баллы), `completed` (`bool`). Все пять ключей обязательны; дополнительные сохраняются без обработки. Новый `id` = `max + 1` (для пустого — `1`); после удаления `id` не перенумеровываются.

При запуске:
- файла нет — пустой список, меню доступно;
- повреждённый JSON / не UTF-8 / неверная структура / повторный `id` — сообщение и завершение **без перезаписи файла**.

## Модули и контракты

| Модуль | Ответственность |
|---|---|
| `logic.py` | Проверка, добавление, поиск, статус, удаление, статистика. Без I/O. |
| `storage.py` | Чтение и запись JSON. Без консольных диалогов. |
| `main.py` | Меню, ввод, сообщения, вызовы функций. |

- `validate_records` — `ValueError` при нарушении; список не изменяет.
- `add_record` — **изменяет** `records` (append); возвращает новую запись.
- `find_records` — **не изменяет** `records`; пустой запрос → `ValueError`.
- `set_completed` / `delete_record` — **изменяют** записи при успехе; `True`/`False`.
- `statistics` — **не изменяет** `records`; возвращает `total`, `completed`, `not_completed`, `total_amount`, `by_category`.
- `load_records` / `save_records` — ошибки (`FileNotFoundError`, `JSONDecodeError`, `UnicodeError`, `ValueError`, `OSError`) — наверх.

Глобальных изменяемых переменных нет.

## Меню

1. Показать (по возрастанию `id`; пусто → «Нет записей»).
2. Добавить (повтор ввода при ошибке; начальный статус — «не решена»).
3. Найти (подстрока без учёта регистра; пустой запрос — ошибка; пусто → «Ничего не найдено»).
4. Изменить статус (явно «решена» / «не решена»; неизвестный `id` — сообщение без изменений).
5. Удалить (только «да» подтверждает; иначе отмена; неизвестный `id` — сообщение).
6. Статистика (всего / решено / не решено / сумма / по категориям по алфавиту).
7. Сохранить (успех — только после фактической записи).
8. Выйти («да» — сохранить; при ошибке остаться в меню; «нет» — выйти без записи; другой ответ — повтор).

## Пример и ожидаемая статистика

Входной `data.json`: 5 записей (см. файл). Ожидание:
- всего **5**, решено **2**, не решено **3**;
- сумма баллов **82**;
- по категориям: **базовые 22**, **словари 20**, **строки 40**.

## Сценарии приёмки

| Сценарий | Результат |
|---|---|
| Файла нет | Пустой список, меню работает |
| `[]` | Статистика: все 0 |
| Записи 4 и 2, вторая решена | Всего 2, решена 1, не решена 1, сумма 6 |
| `  Python  ` | Сохранено `Python` |
| Поиск `PY` при `Python` | Запись найдена |
| Пустой `title` / `amount=-1` / `amount=abc` | Повтор ввода, запись не добавляется |
| Неизвестный `id` при смене статуса | Сообщение, данные без изменений |
| Удаление отменено | Запись сохранена |
| Удалён `id=1` из `[1, 2]` | Остался `id=2`; следующая новая получает `id=3` |
| Сохранение и перезапуск | Все поля восстановлены |
| Повреждённый JSON / повторный `id` | Запуск прекращён, файл не изменён |
| Ошибка сохранения | Нет сообщения об успехе, можно продолжать работу |

## Автоматические проверки

- `test_logic.py`: пустой список, повторные названия, строгие типы (`id=True`, `amount=True`, `completed="false"`), повторный `id`, неизвестный `id` для статуса/удаления, поиск без учёта регистра, статистика по двум категориям.
- `test_storage.py`: сохранение и повторное чтение, кириллица читаема, повреждённый JSON → `JSONDecodeError`, неверная структура и повторный `id` → `ValueError`, отсутствие файла → `FileNotFoundError`.

## путь записи

Меню → `read_non_empty` / `read_int` → `add_record` (вычисляет `id`, ставит `completed=False`, делает `append`) → пункт 7 → `save_records` (`json.dump` в UTF-8) → при следующем запуске `load_records` читает файл, `validate_records` проверяет структуру, запись снова в `records`.
